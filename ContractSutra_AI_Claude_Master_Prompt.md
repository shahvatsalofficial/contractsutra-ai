## 10. Direction-aware compatibility rule matrix

Implement a declarative versioned matrix with test evidence: operation removed, operation added, route renamed, method/security scope changed, parameter removed, parameter requiredness changes, default changes, path/query/header/cookie changes, request body requiredness, field addition/removal, required presence, response guarantee relaxation, primitive or union type changes, enum expansion/contraction, nullable evolution, format constraints, numeric/string bounds, arrays, status codes and media-type changes, components, `$ref` evolution, discriminator/composition, success/error response variants, deprecation/sunset, pagination, backward/forward compatibility, negotiation and SDK decoding behaviors.

Guiding variance: providers must keep accepting old valid **requests** and keep satisfying old promised **responses** to preserve backward compatibility.
