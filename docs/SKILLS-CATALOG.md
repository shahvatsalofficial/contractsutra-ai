# Portable skill catalog

Agent Skills directories use `SKILL.md` metadata and a documented task procedure. These are authored skill files, not evidence of IDE-native execution.

- `openapi-diff` — Compare two local JSON OpenAPI descriptions and produce pointer-level semantic change findings
- `api-contract-check` — Apply conservative request/response compatibility policy to operations
- `consumer-impact` — Associate changes with declared consumer operation usage and preserve unknowns
- `schema-fuzz-plan` — Design safe positive/negative schema-driven cases without live probes
- `deprecation-notice` — Draft pointer-referenced migration and deprecation announcements
- `contractsutra-prime` — Orchestrate requirements, agent delegation, evidence and completion truth
- `spec-intake` — Inspect spec provenance, version, size, format, and unresolved references
- `json-pointer-provenance` — Record reproducible locations and source hashes for every claim
- `change-classification` — Classify breaking, risky, additive and informational changes conservatively
- `request-variance` — Check whether new requests previously accepted remain accepted
- `response-variance` — Check whether old response assumptions remain valid
- `graphql-schema-review` — Plan GraphQL compatibility checks and distinguish SDL parser coverage
- `asyncapi-channel-review` — Plan AsyncAPI 3.1 message/channel analysis
- `protobuf-wire-review` — Plan Protobuf compatibility and Buf validation
- `pact-broker-evidence` — Review genuine Pact contract verification and can-i-deploy output
- `consumer-assumption-registry` — Maintain explicit consumer expectations and operation ownership
- `mock-case-design` — Generate deterministic sample responses and negative cases from supported schemas
- `schema-property-tests` — Design safe property-based tests and verify actual execution before claiming pass
- `ci-compatibility-gate` — Make breaking policies enforceable by deterministic CLI exit code
- `semver-migration` — Plan backward-compatible evolution and migration without automatic release
- `release-notes` — Produce source-linked release communication
- `security-sandbox` — Apply default-deny network, execution, write and plugin installation boundaries
- `secrets-redaction` — Minimize logs, payload and metadata leaks
- `audit-chain` — Verify hash chain and evidence linkage; disclose its non-signature property
- `report-export` — Render JSON, Markdown, escaped HTML, change IDs and reviewable recommendations
- `mcp-connector-design` — Design and test read-only stdio MCP tools behind a project root
- `ide-packaging` — Package least-privilege instruction packs for multiple IDE hosts
- `independent-review` — Challenge tests, parser coverage, security and release assertions
- `server-hardening` — Bound and authenticate loopback read-only reports endpoint
